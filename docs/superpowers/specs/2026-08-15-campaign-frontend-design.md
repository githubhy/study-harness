# Campaign Frontend Design

**Date:** 2026-08-15
**Scope:** repo-wide. Governs the campaign board and every campaign's roadmap and worklog.
**Status:** approved in brainstorm, not yet implemented.

Filed in `docs/superpowers/specs/` rather than inside a campaign because it governs all campaigns.
Campaign-scoped documents live at `campaigns/<name>/`; see `CONTEXT-MAP.md`.

---

## Problem

Three problems, and the third only became visible after the first two were addressed.

**1. The pages make claims that will become false.** Six cards in `roadmap.html` §3 carry a
`not started` chip and the board says `phase 0 · not started`. The moment Phase 0 runs they are
stale, and nothing forces a correction.

**2. Two things the study runs on are not represented.** Threads cross-reference each other
constantly — J asks whether `token-meter` budgets or accounts, which is C's question; O asks whether
the todo list is context or state, also C; E's native-boundary answer sets up H's standard-boundary
one; D gates Phase 3. The plan assumes depth-first work following those references and none are
drawn. Separately the surprise budget — two consecutive unsurprising findings — is per-thread and
displayed nowhere.

**3. Hand-maintenance makes richness unaffordable.** A first pass at this design put all state in a
hand-edited `worklog.html`, which cost seven edits across two files per finding, four of them values
a reader could compute by looking: the strip totals, their copy on the board, the within-band sort
order, and questions written once in a trail entry and again in the frontier. That pressure was
already forcing features *out* of the design — the drawn graph was cut as unmaintainable. The same
pressure explains an existing defect: the fifteen threads' packages are hardcoded **twice** in
`roadmap.html` today, in §4's cards and again in §8's census, with nothing keeping them equal.

Generation removes the pressure. Derived values cost nothing to display when nothing displays them by
hand.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Page split | Stable roadmap + living worklog | A page that claims nothing cannot go stale |
| Source of truth | One `campaign.json` per campaign | Both pages derive from it; they cannot disagree |
| Page generation | **Generated by a Node script** | Reverses the earlier rejection — see below |
| Data format | JSON, not YAML | Node parses JSON with zero dependencies; the repo has no `package.json` |
| Runtime JS | None, still | The generator runs at author time; output is static HTML |
| Audience | The author, in public | Optimise for recall and next-action speed |
| Next-pick drivers | Cross-references and surprise budget | Both were selected; the design serves both |
| Graph rendering | **Drawn SVG, generated** | Reverses the earlier rejection — generation makes it free |
| Strip grouping | Loop bands, fixed alphabetical order within | Stable positions; pips already encode state, so sorting would re-encode it as motion |

**Two reversals, recorded deliberately.** Generation was first rejected as "a toolchain in a repo
that has none", and the drawn graph as "not repaying the layout work at 15 nodes". Both were priced
against hand-maintenance. The repo already requires Node ≥20 and pnpm for the specimen, and the
capture proxy is dependency-free Node, so a dependency-free Node generator is the existing idiom
rather than a new one. Once the graph is emitted from data its maintenance cost is zero.

Still rejected: making lineage the spine of the thread menu (the lineage does not exist yet);
runtime JavaScript and `localStorage` (state belongs in git); a reader-facing findings view (the
audience is the author).

## The four surfaces

| Page | Job | Generated? | Regenerates when |
|---|---|---|---|
| `campaigns/index.html` | Which campaign is hot, where to resume | Yes, from every `campaign.json` | Any campaign's data changes |
| `campaigns/<n>/roadmap.html` | What the campaign is and what it asks | Yes | The thread registry changes |
| `campaigns/<n>/worklog.html` | What has actually happened | Yes | A finding is logged |
| `campaigns/<n>/plan.md` | The executable steps | No — hand-written | Task completion |

All three generated pages are **committed as HTML**, so they open from disk, render on GitHub, and
publish as artifacts with no build step for a reader.

## Data model — `campaigns/<name>/campaign.json`

One file. Two halves: a registry that changes rarely, and a log that grows.

```json
{
  "campaign": "agent-harnesses",
  "title": "Harness Dissection",
  "subject": "agent harnesses as a category",
  "specimen":         { "name": "deepseek-harness", "pinned": "47f9438", "pinnedFull": "47f943859bef60e4160492346772ded9b24f765a", "date": "2026-08-13" },
  "transferSpecimen": { "name": "Claude Code", "via": "local transcripts" },
  "surpriseBudget": 2,
  "canonicalTask": "Create a file called fizzbuzz.js that prints FizzBuzz for 1..20, then run it with node and show me the output.",

  "copy": {
    "standfirst": "Build a transferable model of …",
    "claims":         [ { "title": "You can't read what you can't name", "body": "…" } ],
    "standingOrders": [ { "title": "The surprise budget", "body": "…" } ],
    "sections":       { "s1": "…", "s4": "…", "s5": "…", "s6": "…" },
    "map":            { "lede": "…", "chain": [], "links": [], "outputs": [], "caption": "…" },
    "transferPull":   "…"
  },

  "loopSteps": [
    { "id": "assemble", "label": "Assemble", "step": "Step 1",
      "question": "What goes <b>into</b> the request, and what gets left out?" }
  ],

  "phases": [
    { "id": "0.1", "lane": "ready", "title": "Pin the checkout", "body": "…",
      "pre": "git clone …", "blocks": "nothing", "unblocks": "Task 0.2",
      "produces": ["LLM_BASE_URL_ENV", "DSH_CMD"], "halt": null }
  ],

  "threads": [
    { "letter": "C",
      "name": "Context & compaction",
      "loop": "assemble",
      "question": "What should be dropped when the context fills, and is the decision positional, semantic, or size-based?",
      "raisedBy": { "kind": "toy", "text": ".slice(0, 4000) on every tool result" },
      "packages": ["compaction/*", "context", "spill", "core/session"],
      "needs": "capture",
      "gates": null,
      "entry": "jq -r 'select(.dir==\"request\") …' captures/session-dsh-long.jsonl",
      "detail": ["A monotonic rise followed by a <b>drop in message count</b> is a compaction event. …"] }
  ],

  "infrastructurePackages": ["util", "typert", "test-support", "bundle"],

  "transferLedger": [
    { "q": "Which tools exist and get called", "available": true, "source": "tool_use blocks" }
  ],

  "log": [
    { "thread": "J",
      "date": "2026-08-22",
      "finding": "Hooks CAN block — preventedContinuation on system records.",
      "surprising": true,
      "note": "notes/J-observability.md",
      "opened":   [ { "id": "token-budget-or-account", "q": "Does token-meter budget or account?", "ask": "C" } ],
      "resolved": ["hook-block-or-observe"],
      "issue": null }
  ]
}
```

`raisedBy.kind` is `"toy"` or `"census"` — the two threads the toy could not have suggested (M and N)
use `"census"`, which is how §5's closing row is emitted. `needs` is `"source"`, `"capture"`, or
`"note-2.0"`. `gates` names a phase or is null.

`copy` holds page prose so a different subject can supply its own words without touching templates.
All `copy`, `question`, and `detail` strings may contain a restricted inline HTML subset —
`<b> <i> <em> <strong> <code>` — which the renderer passes through; everything else is escaped.
Those strings store **literal characters**, never pre-escaped entities: `&`, not `&amp;`.

### Fields added during implementation

Building the roadmap renderer surfaced content on the source page that the schema above had nowhere
to put. Each of these exists because omitting it would have silently dropped content during the
migration:

| Field | Shape | Why |
|---|---|---|
| `specimen.repo` | `"owner/name"` | §8's `gh api` package re-check command is rendered from it |
| `threads[].comparison` | boolean | Renders the `t-cc` "CC comparison" marker several thread cards carry |
| `detail[]` entries | string **or** `{ "bullets": ["…"] }` | A string is a paragraph; the object form is the `<ul>` list thread O uses |
| `phases[].halt` | `null` or `{ title, pre, body }` | The halt block on Task 0.2's card — its heading, code block, and warning |
| `copy.map` | `{ lede, chain[], links[], outputs[], caption }` | §2's schematic prose. `chain` is the vertical box sequence, `links` the arrow labels between them, `outputs` the two gated boxes. **Supersedes `copy.sections.s2`, which no longer exists** |
| `copy.transferPull` | string | §6's closing pull paragraph, which carries campaign-specific reasoning |
| `specimen.short` | string | The terse moniker the masthead kicker uses (`dsh`), distinct from the full name in the facts strip |

### Fields added during the migration

Transcribing the real roadmap surfaced four more places where the source page held content the
schema could not. Each was found by the migration acceptance check, and nine of its sixty required
phrases live in the first of them:

| Field | Shape | Why |
|---|---|---|
| `phases[].detail` | array of string \| `{ bullets: [] }` \| `{ pre: "…" }` | Five of six board cards carry prose, a list, or a second code block *after* their command — Phase 1's "Then break it deliberately" list and deliverables, Task 0.2's deliverables, Task 2.0's two closing paragraphs, Phase 3's proof prose, Phase 4's three buckets. Same shape as `threads[].detail` plus a `{ pre }` entry, because Phase 3 interleaves prose, a `<pre>`, and more prose — an order `phases[].pre` alone cannot express |
| `phases[].note` | string or null | The rich clause trailing the "blocked by" line (`· uses the DeepSeek key`, `— it does <em>not</em> wait for the other fourteen`). It carries its own leading separator because the source uses different ones |
| `phases[].consumes` | string or null | Phase 3's fourth `c-blocks` line, `consumes <b>D's "what a new tool must provide" checklist</b>` — the payload of the D → Phase 3 gate |
| `threads[].entry` | now nullable | Five thread cards (K, L, M, N, O) open on reading rather than on a command. A null entry emits nothing rather than an empty `<pre>` box |

`rich()` also stopped escaping `'`. Its output is only ever text content, never an attribute value,
so an apostrophe needs no escaping there — and prose is full of them. `esc()` still escapes it,
because `esc()` output does reach quoted contexts. Without this two acceptance phrases
("You can't read what you can't name", "Analyse, don't dump") could not appear on the page at all.

Two structural rules the renderer follows that are not fields:

- **§5 merges rows by identical `raisedBy.text`.** One toy shortcut may be credited to two threads —
  "Two tools in an array literal" belongs to both D and A — so rows are grouped by exact text, ordered
  by first appearance in `threads[]`, with thread refs joined by ` · `. Modelling `raisedBy` per
  thread and merging at render time avoids a many-to-many relation in the data.
- **§8 groups by loop step**, using the same ordering as the contents rail, §2, and §4, rather than
  sorting all fifteen threads alphabetically. The "Loop step" column is meaningless otherwise.

**`{{canonicalTask}}` is substituted inside `copy.standingOrders[].body`.** The source page quotes the
canonical task *inside* the prose of its "The canonical task" rule rather than in a field of its own,
so a dedicated slot could not position it. The token keeps one source of truth — `data.canonicalTask` —
while letting the prose place it. It is the only token the renderer substitutes; a misspelled one
would render literally, so the page must assert no `{{` survives rendering.

Code fields — `threads[].entry`, `phases[].pre`, and `phases[].halt.pre` — pass through `code()`
rather than `esc()`. `code()` re-permits exactly `<span class="c">`, `<span class="k">`, and `</span>`,
which is what the source uses for comment and keyword highlighting inside `<pre>` blocks and what the
verbatim stylesheet still styles. `checkHtml` counts `span` as a paired tag, so an unbalanced span in
a code field fails the property checks rather than shipping.

`copy.map` exists rather than hardcoding §2's narrative in the renderer because that narrative is
campaign-specific: a different subject has a different dependency story, and prose baked into a
shared template is exactly the drift this design exists to prevent.

The stylesheet keeps its now-unused `.c-state` rule. `theme.mjs` is a byte-verbatim copy of the
source stylesheet, guarded by a test that derives the expected text from the fixture — that invariant
is what proves no styling was lost, and it outweighs deleting one inert rule. The requirement is that
the renderer emit no state chips, not that the stylesheet forget they existed.

## Derived values

Nothing below is stored. All of it is computed, which is the point.

**Thread state.** No log entries → `not-started`. Otherwise let *n* be the number of trailing
consecutive entries with `surprising: false`; `n >= surpriseBudget` → `dry`, else `live`. Because the
count is trailing, a surprising finding resets it — matching the standing order, which the worklog
now *displays* rather than restates.

**Pips.** `surpriseBudget` glyphs, *n* filled: `○○` → `●○` → `●●`.

**Abandonment.** Derived from `dry`. The issue number rides on the log entry that tipped it, so the
one genuinely external fact is recorded once where it happened.

**Frontier.** Every `opened` across the log, minus every id appearing in any `resolved`. Matching is
by `id`, never by question text, so rewording a question cannot orphan it. A question is therefore
written exactly once, in the entry that raised it.

**Strip totals, board resume line, findings counts** — counted from the log.

**Graph edges.** One edge per `opened` entry, `thread → ask`, labelled with the question. Plus one
`thread → phase` edge per non-null `gates`.

**Package census (§8) and the uncovered-package check.** Both from `threads[].packages` plus
`infrastructurePackages` — which kills the double-hardcoding defect: §4 and §8 read the same array.

## Generator

```
tools/build-campaign.mjs            CLI entry; arg parsing, exit codes
tools/campaign/model.mjs            load, validate, derive
tools/campaign/theme.mjs            the CSS block — one definition, all three pages
tools/campaign/html.mjs             escaping and small helpers
tools/campaign/render-roadmap.mjs
tools/campaign/render-worklog.mjs
tools/campaign/render-board.mjs
```

Dependency-free ES modules, Node ≥20, no `package.json`.

```bash
node tools/build-campaign.mjs agent-harnesses     # write the three pages
node tools/build-campaign.mjs --all               # every campaign + the board
node tools/build-campaign.mjs --all --check       # regenerate to memory, diff, exit 1 on drift
```

**Validation — the generator exits non-zero and names the offending path when:**

- a thread letter is duplicated, or is outside `A`–`O`
- a `log[].thread`, `opened[].ask`, or `gates` names an unknown thread or phase
- a `resolved` id was never `opened`
- a `log[].note` path does not exist on disk
- a `thread.loop` names an unknown loop step
- a date is unparseable

Package names are deliberately **not** required to be unique across threads: `sdk` genuinely appears
in both H and N, and `bundle` in both E and the infrastructure list.

**Guaranteed by construction, not by review:** `<meta charset="utf-8">` first; the three-state theme
blocks; no `<script>`, `<link>`, `@import`, or webfont; no `<details>`; `body` background from a
token; every `href="#…"` matching an emitted `id`.

## Page designs

The layouts settled in the brainstorm are unchanged. Only their source changes.

### `worklog.html`

**Coverage strip**, sticky (`position: sticky; top: 0`), pure CSS. Five rows, one per loop step, same
order as the roadmap's §4 bands, letters in **fixed alphabetical order** within a band so a letter
never moves. Not-started renders dashed; live solid with pips; dry solid, struck through. Every letter
anchors to its trail entries.

The header carries `N touched · N dry · N not started` **and a live index** — just the letters
currently live, in most-recently-touched order: `live · J A O`.

This supersedes the "sorted by state within each band" option chosen earlier, and the reason is worth
recording because it is not the cost argument. Sorting was attractive because it made live work drift
left where the eye lands. But it re-encodes as *position* what the pips already encode as *glyph*, and
it means a letter physically moves as it progresses — which forfeits the stable-position property that
was the reason to group by loop band in the first place. The live index buys the same "what's hot"
scan in one row without moving anything. Generation makes both affordable; this is a design choice,
not a budget one.

**Thread graph**, generated SVG below the strip. Nodes positioned by loop band, edges from the
`opened` relation, labelled and colour-coded by target state. This is what the earlier draft cut.

**Frontier** — the open-questions queue, one line each: question, raising thread, answering thread.

**Trail** — append-only, newest first. Thread, pips at that point, date, the finding, the questions it
opened, the note path. Dry entries additionally show the abandonment and issue number, and dim.

Anchors `#tA`–`#tO`, matching the roadmap, linked both ways.

### `roadmap.html`

Structurally as it stands today — §1 loop and claims, §2 map, §3 board, §4 menu in five loop bands,
§5 question index, §6 transfer ledger, §7 standing orders, §8 census. Changes:

1. All six `c-state` chips and the `.c-state` rule are gone. `c-blocks` lines stay: blocking is
   structural, not temporal.
2. Each §4 thread card gains `→ worklog`, anchored to `worklog.html#tX`.
3. §5's question index and §8's census are emitted from `threads[]` rather than written out.
4. Footer gains the worklog link.

### `campaigns/index.html`

Emitted from every `campaign.json`. Per campaign: identity, the three roles, a resume line holding
the newest finding and the same three totals the strip carries, and links to roadmap and worklog.
No hand-copying, so the one-hop rule from the earlier draft is no longer needed at all.

## The update loop

```
1. write the note prose            campaigns/<n>/notes/<LETTER>-<slug>.md
2. append one log entry            campaigns/<n>/campaign.json
3. node tools/build-campaign.mjs --all
4. commit note, data, and pages together
```

One hand edit and one command. Everything else — pips, dry detection, totals, frontier, graph,
census, board — falls out.

## Verification

**Drift:** `node tools/build-campaign.mjs --all --check` regenerates and diffs against the committed
HTML. Drift becomes structurally impossible rather than something a grep might notice, and this
replaces the note/trail parity check the earlier draft relied on.

**Migration acceptance.** Extracting today's 857-line `roadmap.html` into `campaign.json` is the one
genuinely risky step, because it is a hand transcription.

The check must compare against a **pre-migration snapshot**, not against `campaign.json` — comparing
the generated page to the data it was generated from is circular and would pass even if half the
threads were dropped during transcription. So the first task copies the current file to
`tools/campaign/fixtures/roadmap-premigration.html`, and the acceptance check is:

- every content phrase in `tools/campaign/fixtures/acceptance-phrases.txt` appears in the regenerated
  page. That list is committed, not ad-hoc: the 60 phrases used during earlier verification are
  written to the fixture in the same task, so the criterion is reproducible rather than remembered.
- every package named in the snapshot appears in the regenerated page
- zero `<details>`, zero external references
- balanced tags; every `var(--token)` defined in the bare `:root`; every anchor resolving
- `charset` within the first 1024 bytes

A transcription that loses a thread fails on phrases and packages, both sourced from the snapshot.
Once migration is accepted the fixtures stay committed as the regression baseline.

## Out of scope

- Runtime JavaScript, `localStorage`, or any client-side state.
- A reader-facing findings view.
- Watch mode or a dev server. The build takes milliseconds; run it.
- Effort estimates and thread sizing — "cheapest unblocked" was not a selected next-pick driver.
- Generating `plan.md`. It stays hand-written; its checkboxes are not campaign state.

## Deferred

- **Shared copy in `campaigns/_defaults.json`.** Standing orders and the method claims are largely
  repo-wide, but with one campaign the duplication is invisible. Factor it out when a second campaign
  makes it real.
- **Board layout beyond ~3 campaigns.**
- **`campaigns/agent-harnesses/roadmap-samples/`** — three superseded layout candidates carrying stale
  paths, the only stale references left in the repo. Delete when confirmed.
